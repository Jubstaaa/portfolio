## **Main Dashboard Interface**

The dashboard offers a clean and structured interface, allowing developers to monitor application behavior in real-time. Logged events are grouped clearly, making it easy to trace execution flow and identify potential issues.

---

## **Core Features**

### **Request Monitoring**

![Hono Telescope Request Logs](/images/projects/hono-telescope/hono-telescope-request-logs.webp)

Hono Telescope logs all incoming API requests, along with details such as:

- URL & HTTP method
- Response time & status codes
- Request & response payloads
- Timestamp & runtime info

This allows developers to analyze traffic patterns and debug API behaviors efficiently.

---

### **Exception Tracking**

![Hono Telescope Exception Inspector](/images/projects/hono-telescope/hono-telescope-exception-inspector.webp)

Automatic capture and display of unhandled exceptions with stack traces, making debugging runtime errors significantly easier.

---

### **Log Viewer**

![Hono Telescope Logged Console Output](/images/projects/hono-telescope/hono-telescope-logged-console-output.webp)

All console logs (info, warn, error) are collected and displayed within the dashboard, tied to request context where possible.

---

### **Database Query Logging**

![Hono Telescope Query Inspector](/images/projects/hono-telescope/hono-telescope-query-inspector.webp)

Tracks database queries executed by:

- Prisma
- Sequelize
- MongoDB
- Bun SQLite

Query text, bindings, execution time and the parent request are recorded, and a query that fails is marked with the client's own error message, so a failed command is distinguishable from a slow one. Each client is instrumented explicitly — `telescope.instrumentPrisma(prisma)` — rather than by patching globals, which is what makes the capture predictable across Node and Bun.

---

### **MCP Server**

The dashboard endpoint also speaks the Model Context Protocol, so Claude Code, Cursor or any MCP client can read the application's telemetry directly:

```bash
claude mcp add --transport http telescope http://localhost:3000/telescope/mcp
```

Five read-only tools answer a debugging question in one call — the most recent exceptions with the request that produced them and that request's logs and queries, recent requests filtered by status or duration, one request in full, the slowest queries, and the entry counts. No other tool in the Hono ecosystem exposes live request and exception data to an agent.

---

### **Simple Integration**

Three lines: create the instance, mount the middleware, mount the dashboard.

```ts
const telescope = createTelescope({
    storage: memoryStorage({ maxEntries: 1000 }),
})

app.use('*', telescope.middleware())
app.route('/telescope', telescope.dashboard())
```

Telescope is enabled outside production and disabled inside it. If it is enabled in production anyway, mounting the dashboard without credentials throws — the dashboard exposes request bodies, headers and SQL, so that refusal is deliberate. Sensitive headers and body keys are redacted by default at any nesting depth.

## **Tech Stack**

- **Backend:** Hono (Node.js / Bun), TypeScript, ESM only
- **Monitoring Layer:** Instance-based core with pluggable storage, context and collectors
- **UI:** React dashboard bundled and inlined into the package
- **Database Support:** Prisma, Sequelize, MongoDB, Bun SQLite
- **AI Integration:** MCP server over Streamable HTTP, hand-written to keep the package dependency-free
- **Dependencies:** none at runtime; Hono is a peer dependency
- **Open Source:** MIT-licensed GitHub project

---

## **Use Case**

Hono Telescope is designed for developers working with **Hono APIs** who need insight into application internals during development or debugging phases. It provides a transparent, developer-friendly way to track key runtime events and troubleshoot quickly.

---

## **Status**

Published on npm and in active development. 1.0 replaced the original singleton core with an instance-based one: explicit database instrumentation, recursive redaction, a documented storage adapter contract and no runtime dependencies. 1.1 added the MCP server, failed-query marking and outgoing request payload capture.

Planned next: filtering and search in the dashboard, data export, persistent storage adapters and alerting.
