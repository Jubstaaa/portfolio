## **What It Reads**

![A React week — the releases that shipped, then the changes worth knowing about](/images/projects/brief/brief-react-week.webp)

Release notes arrive too late and too rarely — React can go weeks without a release while dozens of meaningful changes land on `main`. So `brief` reads the **commit history** of three repositories every Tuesday instead:

- `facebook/react`
- `vercel/next.js`
- `facebook/react-native`

Each framework gets its own category, archive and weekly page:

- `/react/2026-07-28`
- `/next-js/2026-07-28`
- `/react-native/2026-07-28`

Adding a fourth is one row of config — routes, sitemap, feeds and archives all derive from that list.

---

## **Two Passes, One Call per Change**

Triage reads a week of commit titles per repository and picks only what a working application developer can act on. Drafting then takes each pick on its own and writes three fields: what it means, where it shows up, and whether anything needs doing.

Drafting one change per request rather than batching them is the load-bearing choice: a single malformed response costs one item instead of the whole brief, requests run in parallel, and each stays small enough to finish well inside the timeout.

---

## **Choosing the Model by Measuring It**

The pipeline first ran on a reasoning model, which was slow and — worse — erratic: the same drafting call measured anywhere between 22 and 195 seconds. Two benchmark scripts in the repo call the **production prompts and schemas** against real pull requests, so seven candidates could be compared on latency, completion tokens, schema conformance and whether a usable snippet appeared.

The rejections were about output, not speed:

- **mistral-3-14B** — never produced parseable JSON, and mixed four languages into one sentence
- **llama3.3-70b-instruct** — leaked CJK characters into Turkish prose
- **alibaba-qwen3-32b** — invented a `defineNextConfig` helper that does not exist
- **deepseek-4-flash** — answered triage with the kind `"perf"` against a schema holding `"performance"`, which discards a whole repository's picks

None of that shows up without running the real prompts and reading the result. The winner cut a full run from roughly four minutes to **71 seconds** and removed reasoning from the pipeline.

## **What Reading the Output Caught**

![The result — a React Native change carrying the two lines a team would actually write, and an action telling them what to remove](/images/projects/brief/brief-week.webp)

Two defects survived every passing test, because both produced perfectly valid data:

- **Invented version numbers.** A 2026 React change was reported as _"upgrade to 18.3.0 or later"_. Nothing in the prompt carries release information, so the number was fabricated — in the one field a reader is meant to act on. The prompt now forbids naming a version at all.
- **No usage examples.** The snippet field was described as optional with no sense of when it earned its place, so it stayed empty. Saying plainly that anything the team writes themselves — a config option, a prop, a flag — is _expected_ to carry one fixed it.

---

## **Noise Filtering per Repository**

React Native's stream is far noisier than the other two. In one sampled week, 28 of 81 commits were invisible from the outside: dozens of translation auto-updates, an internal release commit, fifteen identical `RCT_EXPORT_METHOD` removals, and a commit whose title was a file path.

Those patterns live on that repository's own config rather than the shared list — putting them in the shared list would have silently filtered React and Next.js commits too.

## **Architecture Notes**

- **Content is JSON, prose inside it is Markdown.** Each run writes one `weeks/<week>.json` to a Spaces bucket. The `headline`, `detail` and `action` fields hold small Markdown fragments — inline code, bold — rendered through `react-markdown` with GFM and syntax highlighting.
- **The build needs no credentials.** Objects are public-read, so `next build` fetches them with a plain `fetch`, prerenders every framework and week, and emits a static export.
- **No container, deliberately.** The whole site is 1.4 MB of files, so Caddy serves them straight off disk. A container would have added a second web server to do that job on a box with under 300 MB of RAM to spare.
- **Two workflows.** A push to `main` builds and ships without regenerating anything, so a code change costs no inference. The Tuesday cron publishes that week's JSON and then calls the same deploy workflow.
- **Zod validates every model response.** A reply that misses the schema throws with the offending field named, rather than reaching a page.
- **SEO is generated, not hand-maintained.** Sitemap, per-framework RSS, canonicals, JSON-LD and a per-week OG image all derive from the same config the routes do.
