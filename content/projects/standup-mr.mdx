## **The problem it solves**

Most standup tools read your local `git log`. That answers "what did I type", which is not the question a standup asks. Nobody wants to hear a list of commit messages — they want to know what is ready, what is stuck, and why.

standup-mr reads the merge request state instead. Same data your team already argues about in review, turned into a note you can read out loud.

---

## **What makes it different**

Every other tool tells you the pipeline is red. This one opens the failing job's log, extracts the error lines, and puts them in the note.

|                     | commit-log tools | standup-mr                                      |
| ------------------- | ---------------- | ----------------------------------------------- |
| Source              | local `git log`  | GitLab or GitHub API                            |
| Merge request state | ✗                | ready / blocked / draft / stale                 |
| Review queue        | ✗                | pending only, approvals filtered out            |
| Failed pipeline     | ✗                | error lines from the job trace or Actions log   |
| Self-hosted         | varies           | GitLab CE/EE and GitHub Enterprise, first class |

---

## **Two providers, one vocabulary**

GitLab and GitHub are both first class, including self-hosted instances. Identity resolves from a flag, an environment variable, or a logged-in `gh` / `glab` session — and when both are configured, an ambiguous provider fails with a clear error rather than a silent guess.

## **Four surfaces**

### **CLI**

```bash
npx standup-mr fetch              # JSON, provider auto-detected
npx standup-mr fetch --markdown   # structured digest
npx standup-mr post --google-chat "$URL"
```

### **MCP server**

`npx -y standup-mr mcp` starts a stdio MCP server, so any client — Claude Code, Cursor, Codex — can pull the data, read the note-writing rules, and post the finished note to a chat webhook. Three tools, no credential ever accepted as a tool argument.

### **Hosted connector for any AI assistant**

Add `https://standup.ilkerbalcilar.com/mcp` as a remote MCP server in Claude, ChatGPT, Cursor, VS Code, Gemini CLI or Codex, and sign in — with GitHub, with gitlab.com, or with your company's own GitLab or GitHub Enterprise. No API key to paste anywhere. In an assistant with a mobile app, it works from your phone too: ask for your standup on the way to the meeting.

Self-hosted instances are self-service. Type your company's host on the connect page: if a colleague already set up sign-in, you get a button; if not, the page shows the exact redirect URI and scopes to register an OAuth application once, and everyone at that host can sign in from then on.

### **Claude Code skill**

A bundled skill carries the note-writing rules: how to group the previous day by theme, how to derive today from open merge requests, and how to report a blocker from its job log.

## **Engineering notes**

1.0.0 is the first stable release: the CLI flags, the JSON output, the MCP tool names and the environment variables now follow semver. It is published on npm, on the official MCP Registry — with both the npm package and the hosted endpoint — and on Glama, where it scores 100% on the server quality checklist with an A in both server coherence and tool definition quality.

The hosted connector is an OAuth 2.1 authorization server in its own right, built on the MCP SDK: dynamic client registration, PKCE, refresh-token rotation with reuse detection. Provider tokens and webhook URLs are encrypted at rest with AES-256-GCM, its own tokens are stored only as hashes, and the connect page is bound to the browser that started it. Because users can type in any host, every outbound request goes through a guarded fetch whose DNS lookup refuses private addresses at connect time, redirects included. It runs as a single Bun container behind Caddy and Cloudflare, deployed from CI.

Every behaviour is covered by tests — over 400 of them, plus a separate timezone-sensitive suite pinned to two zones, because a standup note is a date calculation wearing a trench coat. Releases run through CI: type check, lint, formatting, tests, build, tag/version agreement, and a smoke test that the published binary runs through its bin symlink.

MIT licensed, no telemetry. The CLI and local server talk only to the host you configure.
