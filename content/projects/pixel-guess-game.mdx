Guess the character before the pixels resolve. Images come from **League of Legends**, **Valorant** and **Demon Slayer**, and the game runs entirely in the browser — no account, no sign-up, nothing to wait for.

---

![Pixel Guess Game Main Game Interface](/images/projects/pixel-guess-game/pixel-guess-game-main-game-interface.webp)

## **How It Works**

- Pick a category.
- A heavily pixelated image appears.
- Guess the character before the pixelation resolves.
- A wrong guess reveals more of the image.
- A correct guess extends your streak.

### **Difficulty**

- **Easy** — lighter pixelation, more to go on from the start
- **Hard** — heavier pixelation plus a grayscale pass, so colour palettes stop being a giveaway

Both effects are applied on a canvas at play time by `use-canvas-pixelation`, not baked into pre-rendered image variants, so one source image serves every difficulty.

---

## **Streaks Stay on the Device**

There is no leaderboard and no account system. `streak-storage` keeps a `streak` and `maxStreak` per category and difficulty in `localStorage`, so progress survives a refresh without a server ever being involved:

```ts
const key = (slug: string, difficulty: Difficulty) =>
    `streak:${slug}:${difficulty}`
```

That is the whole persistence layer. It is also why the web app ships as static files with nothing running behind them.

---

## **One Monorepo, Two Apps**

A Turborepo workspace on Bun holds both clients and the logic they share:

- **`apps/web`** — Vite, React, React Router, Tailwind CSS
- **`apps/mobile`** — Expo and React Native, drawing through Skia with Reanimated for motion
- **`packages/shared`** — the game logic and types both apps import, plus the image pipeline

The iOS app is published as **Pixel Guess**.

---

## **Architecture Notes**

- **Shared logic, not shared UI.** Both apps import types and game rules from `packages/shared`, then build their own interfaces against the platform they run on rather than forcing one component tree across web and native.
- **Image pipeline in the shared package.** `sharp` processes source art and `@aws-sdk/client-s3` uploads it to a DigitalOcean Spaces bucket, with `p-queue` and `p-retry` keeping batch runs bounded and recoverable.
- **Static deployment.** The web build is plain files behind Caddy on a DigitalOcean droplet — no Node process, since there is no server-side work to do.
