# How to Debug Hono Applications with Telescope

> **Updated for 1.x.** The original version of this post used `setupTelescope(app)`. That entry point was removed in 1.0, which replaced the singleton core with an instance-based one. Every snippet below is the current API.

If you've ever used Laravel Telescope, you know how game-changing it is for debugging. Now imagine having that same power for your Hono.js applications.

Introducing **Hono Telescope** — a Laravel Telescope-inspired debugging tool built for Bun and Node.js, specifically designed for Hono developers.

## Why Debugging Matters

Debugging is where we spend most of our development time. But traditional debugging can be frustrating:

- Where did that error come from?
- How long did that database query take?
- Which requests are hitting my API?
- What logs did my app output?

These questions get answered in seconds with the right tool.

## Introducing Hono Telescope

Hono Telescope is a powerful, production-ready debugging and monitoring tool for Hono applications. Works seamlessly with Bun and Node.js.

It captures:

- **HTTP Requests** — Every incoming and outgoing request with headers, payload, and response
- **Exceptions** — Errors with full stack traces
- **Logs** — All `console.log` output organized by level
- **Database Queries** — SQL queries from Prisma, Sequelize, MongoDB, or Bun SQLite with execution times
- **Beautiful Dashboard** — Modern React UI to visualize everything

All in real-time. Zero configuration.

## Quick Start with Bun — 30 Seconds

### Install it

```bash
bun add hono-telescope
```

Or with npm/yarn/pnpm:

```bash
npm install hono-telescope
# yarn add hono-telescope
# pnpm add hono-telescope
```

### Use it

```ts
import { Hono } from 'hono'
import { createTelescope, memoryStorage } from 'hono-telescope'

const app = new Hono()
const telescope = createTelescope({
    storage: memoryStorage({ maxEntries: 1000 }),
})

app.use('*', telescope.middleware())
app.route('/telescope', telescope.dashboard())

app.get('/api/users', async c => {
    console.log('Fetching users')
    const users = await db.query('SELECT * FROM users')
    return c.json(users)
})

export default app
```

Telescope is on outside production and off inside it, so this is safe to leave in place.

### Run it with Bun

```bash
bun run src/index.ts
```

Open `http://localhost:3000/telescope` and start debugging.

## Features in Action

### 1. Request Monitoring

See every HTTP request in real-time:

- Request path, method, and status
- Headers and request body
- Response time
- Request context

Perfect for understanding your API flow during development.

### 2. Exception Tracking

Never miss an error:

- Full stack traces
- Error message and type
- Request that triggered it
- Timestamp

Catch bugs before your users do.

### 3. Database Query Inspection

Monitor database performance:

- Query text and bindings
- Execution time
- Parent request context
- Error information if query fails

Works with:

- **Prisma** — every model operation, through a client extension
- **Sequelize** — all queries
- **MongoDB** — command monitoring
- **Bun SQLite** — prepared statements

Each client is instrumented explicitly, and `instrumentPrisma` returns a new client you have to use:

```ts
const prisma = telescope.instrumentPrisma(new PrismaClient())
telescope.instrumentBunSqlite(db)
```

A query that fails is stored with the driver's own error message, so a failed command does not read as a merely slow one.

### 4. Log Monitoring

Centralized logging:

- `console.log` capture
- Organized by severity level
- Linked to the request they happened inside

All your debug logs in one place.

## Configuration

Want fine-grained control?

```ts
const telescope = createTelescope({
    enabled: process.env.NODE_ENV !== 'production',
    storage: memoryStorage({ maxEntries: 1000 }),
    collectors: [consoleCollector(), exceptionCollector(), fetchCollector()],
    dashboardPath: '/telescope', // must match the path you mount at
    ignorePaths: ['/health'],
    capture: { requestBody: true, responseBody: true, maxBodySize: 65536 },
    redact: {
        headers: ['authorization', 'cookie', 'x-api-key'],
        bodyKeys: ['password', 'token', 'secret'],
    },
    dashboard: { auth: { username: 'admin', password: 'telescope' } },
})
```

Every option is optional. Redaction is on by default and recurses through nested objects and arrays, so a `password` five levels deep in a request body is still replaced before anything is stored.

## Live Demo — Try It Now

No installation needed. [Live dashboard](https://hono-telescope.ilkerbalcilar.com/telescope).

Test the API:

```bash
BASE=https://hono-telescope.ilkerbalcilar.com

# Incoming request plus the SQLite queries it ran
curl $BASE/api/users

# Outgoing POST whose payload is recorded with `token` redacted
curl -X POST $BASE/api/webhook

# A UNIQUE violation, recorded as a failed query; returns 409 and throws nothing
curl -X POST $BASE/api/db-error

# Throws, so the exception is recorded as a child of its request
curl $BASE/api/error
```

Then check the dashboard to see everything. The demo store is capped at 500 entries in memory and has no auth, so treat anything you send as public.

## Perfect For

- **Development** — debug during active development with Bun's speed
- **Testing** — understand request/response flows
- **Performance** — track database query times and optimize
- **Staging** — reproduce a report with the request, its queries and its logs in one view
- **API development** — monitor API behavior

It is a development tool, not an APM: in production it is disabled by default, and enabling it there without dashboard credentials throws on purpose.

## Why Bun + Telescope

Bun is lightning-fast. But you still need to see what's happening in your app. Hono Telescope gives you that visibility with zero overhead.

Perfect combo for modern API development.

## Read Your App's Errors From Your Editor

The dashboard endpoint is also an [MCP](https://modelcontextprotocol.io) server, so an AI coding agent can read the running application instead of being handed pasted stack traces:

```bash
claude mcp add --transport http telescope http://localhost:3000/telescope/mcp
```

Five read-only tools: `recent_exceptions` (each exception with the request that produced it and that request's logs, queries and outgoing calls), `recent_requests` (filter by `minStatus`, `status`, `minDuration`, `uriContains`), `request_detail`, `slow_queries` and `stats`. Ask "why did that request fail" and the agent has the whole failure in one call.
